# Layout

| Path | Role |
| --- | --- |
| `conf/` | Hydra YAML: `config.yaml` plus groups `models`, `training/measurements`, `training/readout`, `training/regression`, and `evaluation`, mirroring `src/QELM/` |
| `main.py` | Entrypoint. Seeds NumPy, loads `.env`, prints the selection, and runs the pipeline |
| `src/QELM/models/` | `TransverseFieldIsingModel` (dense TFIM Hamiltonian), the `KitaevModel` scaffold, the time-evolution stub, and the random brickwork circuits `circuits/` (issue #189): `base.py` holds `BrickworkCircuit` (geometry, drawing and applying the layers) and the gate application, `haar.py` the U(1) and Haar gates with `U1BrickworkCircuit` and `HaarBrickworkCircuit`, `clifford.py` the two-qubit Clifford group and `CliffordBrickworkCircuit`; `QELM.models.circuits` re-exports them all |
| `src/QELM/physics/` | Quantum primitives only (`operators.py`): Pauli matrices `I, X, Y, Z`, `pauli(label)`, `get_site_operator(op, site, N, sparse=False)` (dense array by default, CSR with `sparse=True`) and `qubit_counts(rho, Nr=0)`, which returns `(N, Ns, Nr)`; `partial_trace.py`: `partial_trace(state, keep)`, the reduced density matrix `rho_A = Tr_B(rho)` of the qubits `keep` (in that order), from a state vector (via its amplitude matrix, without forming `rho`), a dense or a sparse `rho`; `charge.py` (issue #134): the global charge `Q = sum_i b_i` of a state, `charge_values(N, sites)`, `charge_distribution(state)`, `total_charge(state)`, `sharp_charge(state)` and `charge_leakage(state, Q)`, the weight outside the sector `Q` (`batch_charge_leakage` for a batch of vectors) |
| `src/QELM/encoding/` | Initial-state encodings (renamed from `embedding/`, issue #197). An encoding subclasses `Encoding` (`base.py`): `N` is the total qubit count, so `state(x)` returns `psi` of shape `(2**N,)` (or a CSR column of shape `(2**N, 1)` with `sparse=True`; `density_matrix(x, sparse=True)` likewise returns a CSR matrix) and `density_matrix(x)`, or its short name `rho(x, sparse=False)`, returns `rho`, like the models built with the same `N`. Ancillas are the first sites (most significant bits), before the `Ns = N - Nr` system qubits. `AncillaChargeSectorEncoding` prepares `(|0>_R|Q=Ns//2>_S + |1>_R|Q=Ns//2-1>_S)/sqrt(2)` with one ancilla and `Ns = N - 1`; `RotationEncoding` (`rotation.py`, issue #181) encodes a static input of `N` angles as the product state `R_a(x_0)|0> ⊗ ... ⊗ R_a(x_{N-1})|0>`, `a = x` or `y`, with `states(x)` for a batch and `bloch_vectors(x)` in closed form; `get_encoding(name)` returns the class for a config key |
| `src/QELM/training/` | The QELM data pipeline, one subpackage per domain; in each, `base.py` holds the parent class and every child class has its own module. Everything is importable from `QELM.training`. `measurements/`: `base.py` `Readout`, whose `measure(rho, p=None, rng=None)` returns `ReadoutResult(outcomes, rho)` with the post-measurement state (each target qubit is measured with probability `p`, outcome `nan` when not measured); `projective.py` `ProjectiveMeasurement`, which reads `p` from its config block when `measure` gets none (1.0 if the block has none); `get_readout(name)` returns the class for a config key. `readout/`: features computed from the final state without disturbing it, `base.py` `Observables`, `single.py` `SingleObservable`, `double.py` `DoubleObservable`, which return `Tr(rho O_k)`. `dataset.py`: `create_qelm_dataset(M, X, y)` builds `QELMDataset(phi, y)` with `phi = [M || X]` (mid-circuit outcomes then final readout of S) and `y` the ancilla outcome; `split_dataset(ds, train_fraction)` gives disjoint train and test sets. `regression/`: `base.py` `Trainer`, `linear.py` `LinearReadout` (`linear`), `ridge.py` `RidgeReadout` (`ridge`) (`training.alpha = 0` is allowed: `W = pinv(Phi) @ y`, the limit `alpha -> 0`, least squares above `n_samples = rank(Phi)` and the minimum-norm interpolation below, issue #181) |
| `src/QELM/datasets/` | Static classification datasets (issue #181). `images.py`: `read_idx` (the IDX format of MNIST), `download_mnist(root)` (the four files, once, checked against their SHA-256), `load_mnist`, and `load_digit_classes(dataset, classes)`, the task between two or more digits of MNIST or of scikit-learn's 8x8 digits (bundled, no download), image of digit `classes[k]` labelled `k`; `preprocess.py`: `AngleEncoder(n_components)`, a PCA fitted on the training images, each component mapped linearly to `[0, pi]` |
| `src/QELM/evaluation/` | Post-training analysis only: metrics (`metrics.py`: `MSE`, `NMSE`, `R2` (coefficient of determination); all inputs are checked to be 1-D, non-empty and of the same shape; `von_neumann_entropy(rho, N)`, the entanglement entropy of the ancilla qubit 0, in bits by default, for a dense or sparse `rho`), entanglement entropies of any subsystem `A` (`entropy.py`, issue #93: `renyi_entropy(state, n, sector_A)` for any order `n >= 0` including `0`, `1`, `2` and `inf`, `von_neumann_entropy(state, sector_A)` and `entanglement_spectrum(state, sector_A)`, in bits by default, for a state vector, a dense or a sparse `rho`; importable from `QELM.evaluation`), the charge conservation filter (`charge_conservation.py`, issue #134: `conserved_mask`, `conservation_metrics` and `charge_filter`, which applies the `charge_conservation` config block) the double-descent sweep (`double_descent.py`, issue #181: `observable_operators`, `expectations`, `product_state_features` (the observables of a product state in closed form), `random_features` (classical ELM), `one_hot`, `predict_classes`, `double_descent_sweep`, the train and test errors of the ridge readout on one-hot targets against `alpha = n_train / rank`, `full_pool_fit`, the accuracy and confusion matrix of the readout fitted on the whole pool), the NumPy K-NN (`knn.py`, issues #214 and #213: `CustomKNN(n_neighbors=None, ties="average", metric="euclidean", rtol=None)` with `fit`, `kneighbors`, `predict`, `predict_proba` and `score`, the inverse-distance vote of `KNeighborsClassifier(weights="distance")` with the Euclidean distance or, with `metric="mahalanobis"`, the Mahalanobis distance `sqrt((x - y)^T Sigma^+ (x - y))` whose metric is the pseudo-inverse of the covariance of the training set (attributes `covariance_`, `precision_`, `rank_`), `K = round(sqrt(n_train))` by default (`default_n_neighbors`); the points tied with the `K`-th neighbor share its free places (`ties="average"`, independent of the order of the training set) or are taken by lowest index (`ties="index"`)) and plots (`plots.py`, scaffold) |
| `src/QELM/utils/` | Helpers shared by the experiment scripts. `io.py`: `save_results(results, out_dir, exp_name, features="X")` writes the arrays to `<exp_name>.npz` and the scores to `metrics.json`; each script passes `Path(__file__).stem`, so two experiments never share a file name; `save_config(cfg, out_dir)` writes `resolved_config.json`, the config with every `${...}` evaluated to the number it gives (issue #85); `sweep.py`: `load_sweep(sweep_dir)` returns one row per run folder (`N`, `seed`, `p`, `L` read from its `.hydra/config.yaml`, plus `metrics.json`), `summarize(rows, by=("N", "p"))` averages the metrics over the seeds (mean, std, standard error), `latest_sweep(root)` returns the newest `<date_time>` folder; `live.py`: `run_with_progress(cmd, total, env)` runs the sweep launcher with one tqdm bar for the whole sweep, one step per run, and the runs' own bars turned off |
| `src/QELM/pipeline.py` | Routes the `models` key to a model, a trainer, and an evaluator, then saves a checkpoint |
| `src/QELM/checkpoint.py` | Writes the `.npz` checkpoint |
| `src/QELM/config.py` | `load_config` composes `conf/` with overrides, from any working directory |
| `src/QELM/resolvers.py` | `mul`, `div` and `int` resolvers for derived values in `conf/` |
| `src/QELM/seed.py` | Reads `seed` from the composed config |
| `src/QELM/selection.py` | Loads `.env` and formats the selection line |
| `data/` | Local datasets. Gitignored, and not created by the package |
| `notebooks/benchmarks/` | Benchmark notebooks, each reproducing a published figure: `01_learnability_accuracy.ipynb` (Barratt et al. 2022, Fig. 2b, issue #113), `02_learnability_entropy.ipynb` (Fig. 2c, issue #115), `03_charge_sharpening.ipynb` (Agrawal et al. 2024, Fig. 7, issues #137 and #142) |
| `notebooks/results/` | Notebooks producing new results: `02_QELM_M_analysis.ipynb` (runs the `exp_QELM_M` sweep over `p`, reads it back and plots the metrics against `p`, issue #94, in a performance figure and an entanglement figure, then sweeps `p` for two fields `h` and two sizes `N`, issue #174), `03_QELM_M_alpha_ratio.ipynb` (runs the `exp_QELM_M_ratio` sweep over the sample-to-parameter ratio and plots the NMSE against it, issue #96, then draws one heatmap per metric over the grid of `p` and the ratio, issue #164), `04_QELM_Q_measurements.ipynb` (runs the `exp_QELM_Q` sweep over `p` and plots the accuracy on the charge `Q` against `p`, for the readout of `<Z_k>` and of each of `<X_k>`, `<Y_k>`, `<X_i X_j>`, `<Y_i Y_j>`, `<Z_i Z_j>`, `<X_i Y_j>`, then against the evolution time at `N = 6`, issue #163), `05_QELM_M_circuits.ipynb` (the same sweep with the TFIM, a Haar circuit and a Clifford circuit as the unitary dynamics, and the three compared, issue #171), `07_double_descent_mnist.ipynb` (double descent of the QELM on MNIST digits against `alpha = n_train / n_features`, with the classical ELM and `t = 0` checks and the confusion matrices, issue #181) |
| `src/QELM/utils/plots/` | Plotting helpers shared by the experiment scripts and the notebooks (issue #147), imported as `QELM.utils.plots` and kept out of `QELM.utils` because Matplotlib is a dev dependency. `style.py`: the project style (`subplots`, `style_axes`, `apply_style`: no grid, a box closed on four sides, large bold titles) and `COLORS`; `sweep.py`: `sweep_curve` (one size of a summarized sweep, with the standard error over seeds or the run's own error), `draw_curve`, `draw_references`, `compare_same_size`, `print_comparison`; `heatmap.py`: `sweep_grid` (one metric of one size of a two-parameter sweep on its grid), `cell_edges` (cells centered on the grid points, geometric on a log axis), `draw_heatmap` (`pcolormesh` with its colorbar, optional log color scale; issue #164); `io.py`: `save_figure(fig, out_dir, name)` writes `<name>.png` and `<name>.json`, the data of every curve, error bar, histogram and heatmap drawn (`figure_data`) |
| `experiments/` | One folder per experiment, each holding its Python script and the bash launcher of its sweep: `example/` (`run_experiment.py`, an executable Hydra template that composes `conf/config.yaml` and seeds NumPy, and `test_experiment.sh`), `projective/` (projective readout), `QELM_Z/` (QELM on the final observables), `QELM_M/` (QELM on the measurement record), `QELM_Q/` (QELM on the charge `Q` from the final `<Z_k>`, with intermediate Z measurements, issue #163, `plot_knn.py`, the K-NN readouts of a sweep against `p`, issue #214, and `plot_knn_metrics.py`, which compares the ridge readout with the Euclidean and Mahalanobis K-NN, issue #213), `double_descent/` (double descent of the QELM on MNIST digits, issue #181). `scratch/` is where experiments write temporary outputs; everything in it except `.gitkeep` is gitignored |
| `tests/` | pytest |

Import the library as `QELM`.

## What one run does

`run_pipeline` resolves names, then calls the selected pieces:

1. `cfg.models` selects `TransverseFieldIsingModel` (`TFIM`) or `KitaevModel` (`kitaev`). `from_config` copies the scalar keys in that simulation block.
2. `cfg.training.name` selects `RidgeReadout` (`ridge`) or `LinearReadout` (`linear`). `RidgeReadout` reads `alpha` from `conf/training/regression/ridge.yaml` (default 1e-3) and solves `(Phi^T Phi + alpha I) W = Phi^T y`; `fit(phi, y, alpha=...)` overrides `alpha`.
3. `evolution_request(model, dt=..., n_steps=...)` (in `QELM.models.base`) records `dt` and `n_steps` from `cfg.evolution` and sets `status` to `scaffold`. It does not allocate a trajectory. `hamiltonian` builds the dense TFIM matrix of shape `(2**N, 2**N)` but the pipeline does not call it yet; the Kitaev scaffold raises `NotImplementedError`. `HamiltonianModel.propagator(dt=...)` returns `exp(-i H dt)`, and `model.evolve(state, dt=None)` applies it without forming `U` (with no `dt`, it uses `model.dt`, which `from_config` sets from `evolution.dt`): a state vector `psi` of shape `(dim,)` comes back as `U psi`, a density matrix `rho` of shape `(dim, dim)` as `U rho U^dagger`, and any other shape raises `ValueError`. The pipeline does not call `evolve` yet.
4. `trainer.fit(features=None, targets=None)` returns `"scaffold"`, since the pipeline does not build a dataset yet. No weight vector is estimated, so `state_dict` stores a length-0 `float64` array under `weights`. With real features, `RidgeReadout.fit` returns `"fitted"`, `predict` returns `Phi @ W` and `state_dict` stores `W`.
5. The `default` evaluator lists the metric names and plot name from `cfg.evaluation` and returns `status=scaffold`. It does not score predictions or write an image.
6. `save_checkpoint` writes the archive described in [Checkpoints and local data](checkpoints.md).

The printed pipeline line names the model, the trainer, `dt`, `n_steps`, the evaluator report, and the checkpoint path.
